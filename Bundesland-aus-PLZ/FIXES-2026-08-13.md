## 🔴 B1 — Lokale Datei und Editor sind auseinander

`CUTOFF_ENABLED` / `CUTOFF_DATE` (Zeile 89–90) und die Nutzung in
`fillBundeslandForDeal()` (Zeile 198) stehen **nur lokal**, sind laut Projektstand nie in den
Apps-Script-Editor kopiert worden.

Zwei Konsequenzen:
1. Der Editor läuft mit einer anderen Logik als die Datei, die du hier liest.
2. Ein `clasp pull` (via `sync-all-scripts.ps1`) überschreibt die lokale Änderung **kommentarlos**
   und committet die Rücknahme als "Sync vom …".

**Tun:** entweder Code in den Editor einspielen, oder — wenn CUTOFF gar nicht gebraucht wird —
lokal wieder rausnehmen. Nicht in diesem Zustand lassen.

## 🔴 B2 — Konfigurationsfehler tauchen in der Zusammenfassung nicht auf

`fillBundeslandForDeal()` kann `FEHLER (Option-ID für … fehlt)` zurückgeben (Zeile 226).
Die Auswertung in `fillBundeslandForAllDeals()` (Zeile 128–130) kennt aber nur
`gesetzt` / `DRY-RUN` / sonst → **jeder Konfigurationsfehler landet stumm im
`uebersprungen`-Topf.** Das Montagepartner-Script hat dafür einen eigenen `fehler`-Zähler,
dieses nicht.

Genau das ist die Klasse Fehler, die im 6570er-Lauf zwischen ein paar tausend Zeilen untergeht.

**Tun:**
```js
const summary = { gesetzt: 0, uebersprungen: 0, dryRun: 0, fehler: 0, grenzfaelle: 0, ausAdresse: 0 };
// ...
else if (result.startsWith('FEHLER')) summary.fehler++;
else summary.uebersprungen++;
```
plus am Ende die Warnzeile analog zum Montagepartner-Script.

## 🟡 B3 — Nulllauf-Erkennung fehlt

Das Montagepartner-Script hat den Hinweis "kein einziger Deal zugeordnet → Reihenfolge prüfen".
Hier gibt es kein Gegenstück. Läuft das Script mal über einen Bestand, in dem alles schon
gesetzt ist (oder mit falschem Feldschlüssel), sieht ein Nulllauf identisch aus wie ein
sauberer Lauf.

**Tun:** wenn `gesetzt + dryRun === 0 && processed > 0`, eine deutliche Zeile ins Log —
und die Zahl fürs Dashboard mitgeben (siehe `ARCHITEKTUR-2026-08-13.md`, Status
`KETTE_BLOCKIERT`).

## 🟡 B4 — Grenzfall-Liste ist veraltet

`fillBundeslandForAusgewaehlteDeals()` (Zeile 181) enthält die 9 Grenzfall-Deals aus dem
**1200er-DRY-Lauf**. Der echte Vollauf ging über 6570 Deals und hat mindestens einen weiteren
gefunden (Deal 6885, PLZ 2460, Bruckneudorf/Bruck a.d. Leitha).

**Tun:** Log-Sheet `LOG_Bundesland aus PLZ (V3)` nach `GRENZFALL` filtern, die tatsächliche
Liste hier eintragen — und dann abarbeiten. Solange die Grenzfälle offen sind, bekommen diese
Deals auch keinen Montagepartner.

## 🟡 B5 — `plzAusFreitext()` kann eine Hausnummer für eine PLZ halten

```js
const kandidaten = String(text).match(/\b\d{4}\b/g) || [];
for (const k of kandidaten) { if (PLZ_BUNDESLAND[k]) return k; }
```
Nimmt die **erste** vierstellige Zahl, die im PLZ-Verzeichnis existiert. Bei
`"Wiener Straße 1220"` wäre das die Hausnummer, nicht die PLZ — und 1220 ist eine gültige
Wiener PLZ. Betrifft nur den Fallback-Zweig (PLZ-Feld leer), im letzten Lauf 2 Deals, also
heute klein. Wächst aber mit, wenn das Adressfeld öfter zur Quelle wird.

**Tun:** Kandidaten bewerten statt den ersten zu nehmen — bevorzugt eine Zahl, auf die ein
großgeschriebenes Wort folgt (`1220 Wien`), sonst die letzte im String. Und in jedem Fall
`fund.quelle === 'adresse'` im Log lassen, damit die Fälle prüfbar bleiben (ist schon so).

## ⚪ B6 — Personen-Vorabladung bei jedem Resume neu

`ladePersonenIndex()` lädt 6728 Personen (≈68 Seitenabrufe, ~20–30 s) bei **jedem** Start,
auch beim Fortsetzen eines pausierten Laufs. Bei mehreren Resumes summiert sich das.
Heute unkritisch (der Vollauf ging in einem Rutsch durch), relevant, sobald der Bestand wächst.

**Tun (nur falls nötig):** nichts überstürzen — messen. Erst wenn ein Vollauf regelmäßig
3+ Resumes braucht, lohnt ein Cache.

## ⚪ B7 — Log-Puffer wird komplett im Speicher gehalten

`_logBuffer` sammelt alle Zeilen und schreibt sie am Ende in **einem** `setValues()`.
Bei 6571 × 14 Zellen ist das nachweislich in Ordnung. Bei deutlich mehr wird es eng.

**Tun:** ab z.B. 5000 gepufferten Zeilen zwischendurch flushen. Ein Dreizeiler in `logRow()`.

---

## ⚪ B8 — Log schreibt weiterhin jede Zeile, auch "bereits gesetzt"

Im Dauerbetrieb (falls dieses Script mal einen Trigger bekommt) wären das ~6500
Nichts-passiert-Zeilen pro Lauf. Siehe Logging-Doktrin in `ARCHITEKTUR-2026-08-13.md`:
`übersprungen (bereits gesetzt)` gehört in `Logger.log`, nicht ins Sheet.

Für manuelle Vollläufe bewusst so lassen — der Unterschied greift erst beim Trigger.
